# Open questions (Phase B, draft V1.1)

The draft schema already follows the recommended default for every row. Changing a default changes the named tables. Decided items are listed at the end for the record.

## Open

| #   | Area         | Question                                                                                                                                                                            | Recommended default (used in the draft)                                                                                                                   | Affects                            |
| --- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| Q0  | OTP          | **Blocker:** replace the fixed OTP (`999999`, `OTP_PROVIDER=fixed`) with a real SMS provider before any production launch                                                           | Must be done before production; startup already refuses `fixed` in production. Needs the SMS provider decision (DLT registration lead time in India)      | `OtpProvider`, ops                 |
| Q1  | Privacy      | Optional health fields (blood group, height, weight) are sensitive personal data. Encrypt them at column level now, or keep them plain with restricted reads until the DPDP review? | Plain columns, readable only by leadership, Admin, the student and linked parents; listed in the DPDP review with phone/email. No column encryption in V1 | `students`                         |
| Q2  | Approvals    | V1.1 says "teacher addition/update". Is a teacher **update** a separate approval type?                                                                                              | Yes: `teacher_update` added to `approval_type` (7 values)                                                                                                 | `approval_requests`, enum          |
| Q3  | Substitutes  | The design scope gives the VP a substitute-management screen; V1.1 says Admin assigns substitutes.                                                                                  | Admin assigns; VP sees substitutions read-only                                                                                                            | permissions, screens               |
| Q4  | Imports      | Teaching-staff Excel import: one approval for the whole job, or one per teacher?                                                                                                    | One `teacher_addition` approval per import job (approver sees the list); rejected rows can be fixed and re-imported                                       | `import_jobs`, `approval_requests` |
| Q5  | Guardians    | Limit on guardians per student (S1 mitigation)?                                                                                                                                     | 4 per student, enforced by the app; per-school setting later                                                                                              | `student_guardians`                |
| Q6  | Guardians    | When a guardian mobile changes, how is the old holder told (no SMS notifications)?                                                                                                  | Push + in-app to the previously linked parent user, if any; audit row always                                                                              | `notifications`                    |
| Q7  | Guardians    | Revoke parent links on guardian change in app code or by trigger?                                                                                                                   | App code in the same transaction (testable, visible); trigger only if a second write path appears                                                         | `parent_student_links`             |
| Q8  | Retention    | Audit log retention                                                                                                                                                                 | 3 years, then drop monthly partitions; confirm in the DPDP review                                                                                         | `audit_logs`                       |
| Q9  | Retention    | In-app notification retention                                                                                                                                                       | 90 days (drop monthly partitions)                                                                                                                         | `notifications`                    |
| Q10 | Retention    | Import raw rows (personal data)                                                                                                                                                     | Purged 30 days after the job closes                                                                                                                       | `import_rows`                      |
| Q11 | Exams        | Grading scheme (marks → grade)                                                                                                                                                      | No grading table in V1; the app computes the grade from a fixed default band and stores it in the snapshot. Per-school scales later                       | `student_results`                  |
| Q12 | Exams        | Half marks allowed?                                                                                                                                                                 | Yes, `numeric(6,2)`                                                                                                                                       | `marks_entries`, `exam_subjects`   |
| Q13 | Teachers     | Assigning a subject the teacher is not qualified for                                                                                                                                | Warn, do not block                                                                                                                                        | app                                |
| Q14 | Codes        | School code after `sch9999`                                                                                                                                                         | Grows to `sch10000` (CHECK allows 4+ digits); usernames likewise grow past 4 digits                                                                       | `schools`, `users`                 |
| Q15 | Students     | Admission number: keep as an optional field (many Indian schools use one)?                                                                                                          | Optional, unique per school when present                                                                                                                  | `students`                         |
| Q16 | Photos       | Student/parent/teacher profile photos                                                                                                                                               | Not stored in V1                                                                                                                                          | `files`                            |
| Q17 | Notices      | Notice attachments                                                                                                                                                                  | None in V1                                                                                                                                                | `notices`                          |
| Q18 | Attendance   | Marking on holidays or non-working days                                                                                                                                             | App warns and blocks by default; Admin can override with a reason                                                                                         | app                                |
| Q19 | Leave        | Half-day leave                                                                                                                                                                      | Not in V1 (whole days)                                                                                                                                    | `leave_requests`                   |
| Q20 | Homework     | Who marks completion: teacher only, or student self-mark?                                                                                                                           | Teacher only                                                                                                                                              | `homework_completions`             |
| Q21 | Partitions   | How are monthly partitions created?                                                                                                                                                 | Worker job creates the next 3 months ahead; no extension needed (works on any Postgres host)                                                              | ops                                |
| Q22 | Platform     | Verifier and Super Admin screens are not in the design scope                                                                                                                        | Minimal internal web page later; V1 starts with API routes + seeded platform staff                                                                        | platform routes                    |
| Q23 | Non-teaching | Final designations and which non-teaching staff manage inventory                                                                                                                    | All non-teaching staff get `inventory.manage` until departments are confirmed                                                                             | permissions                        |
| Q24 | Branding     | School colours on the branding screen                                                                                                                                               | Not stored until confirmed (`schools.brand_color` ready to add)                                                                                           | `schools`                          |
| Q25 | Principal    | Does the Principal also need a `staff` row (attendance, leave)?                                                                                                                     | Optional: created only if the school wants the Principal in staff attendance                                                                              | `staff`                            |
| Q26 | Directory    | School directory seed source (existing open decision)                                                                                                                               | Platform staff add directory entries manually (`status = unclaimed`) until a data source is chosen                                                        | `schools`                          |
