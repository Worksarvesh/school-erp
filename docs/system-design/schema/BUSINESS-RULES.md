# Business rules → enforcement (draft V1.1)

Each rule from the V1.1 locked decisions, and where it is enforced. **DB** = constraint, unique index or foreign key. **Trigger** = PostgreSQL trigger. **RLS** = row policy ([RLS-MATRIX.md](RLS-MATRIX.md)). **App** = API service or guard check (with a test). Where a rule can be held by the database, it is; app checks cover what a constraint cannot express.

## Accounts and authentication

| #   | Rule                                                                                                                           | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1  | Principal logs in with mobile + OTP; new principal waits for verifier approval; unverified principal sees no school data       | App (OTP flow); principal membership created only when `school_verification_requests.status = approved`; no membership = guard 404 on every school route                                                                                                                                                                                                                                                                                                                                                           |
| A2  | Verification target 48 h, never auto-approved                                                                                  | App (no auto-approve job); `decided_by_staff_id` required to approve (DB CHECK: `status <> 'approved' OR decided_by_staff_id IS NOT NULL`)                                                                                                                                                                                                                                                                                                                                                                         |
| A3  | "School not listed" needs name, address, PIN                                                                                   | DB CHECK on `school_verification_requests`: exactly one of `school_id` or `proposed_name`; when `proposed_name` is set, `proposed_address` and `proposed_pin_code` are NOT NULL; PIN CHECK `^[1-9][0-9]{5}$`                                                                                                                                                                                                                                                                                                       |
| A4  | Rejection reason mandatory (verification)                                                                                      | DB CHECK `status <> 'rejected' OR length(trim(decision_reason)) > 0`                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| A5  | Staff and student usernames `sch0001e0001` / `sch0001s0001`, no collisions                                                     | DB: `schools.code` CHECK `^sch[0-9]{4,}$` from `school_code_seq`; `username_sequences` row-locked allocation; `users.username` UNIQUE; CHECK `^sch[0-9]{4,}[es][0-9]{4,}$`                                                                                                                                                                                                                                                                                                                                         |
| A6  | Temporary password: 6 unique alphanumeric characters, hashed only, shown once                                                  | App (generator, argon2id hash into `credentials`); `credential_issuances.shown_at` set once (App: second display refused); plaintext never stored, logged or audited (existing log-scrubbing test extended)                                                                                                                                                                                                                                                                                                        |
| A7  | First login forces a password change                                                                                           | `credentials.must_change_password = true`; App: guard allows only `POST /v1/me/password` and logout until changed                                                                                                                                                                                                                                                                                                                                                                                                  |
| A8  | Password resets: VP/Admin by Principal; Teacher/Non-Teaching/Student by Admin; Principal by Super Admin; never show a password | Permission `credentials.reset` scoped by target role (App); principal recovery = Super Admin phone change on the platform path (App + audit); reset issues a new temp password (`credential_issuances.kind = reset`)                                                                                                                                                                                                                                                                                               |
| A9  | Parent: mobile + OTP; if the number is not found, generic message, no OTP sent, show Contact Support                           | App (same response shape and timing for found / not found; rate limits per IP and per phone)                                                                                                                                                                                                                                                                                                                                                                                                                       |
| A10 | Parent sees only students whose active guardian mobile matches the verified number, across schools                             | `parent_student_links` written only by SECURITY DEFINER `auth_sync_parent_links`; RLS O + R-stu; guard 404 without an active link                                                                                                                                                                                                                                                                                                                                                                                  |
| A11 | Student-entered guardian mobile does not grant access until Admin confirms                                                     | `student_guardians.status = pending` when `source = student_profile` (App); link sync reads only `status = active`                                                                                                                                                                                                                                                                                                                                                                                                 |
| A12 | Multiple guardians per student                                                                                                 | DB: unique `(school_id, student_id, mobile)` only, no limit on rows; App: optional per-school limit (S1 mitigation)                                                                                                                                                                                                                                                                                                                                                                                                |
| A13 | Guardian mobile change or removal revokes access                                                                               | App: in the same transaction, revoke matching `parent_student_links` + audit; Trigger alternative noted in OPEN-QUESTIONS                                                                                                                                                                                                                                                                                                                                                                                          |
| A14 | OTP: 6 digits, 5 min expiry, 5 attempts, one open challenge per number and purpose, codes never stored or logged               | `otp_challenges.code_hash` only; DB CHECK `attempts <= max_attempts`; SECURITY DEFINER verify increments attempts atomically and marks the challenge consumed; creating a challenge consumes any open one for the same phone + purpose (App); rate limits per phone and per IP on send and verify (App)                                                                                                                                                                                                            |
| A15 | Fixed OTP `999999` for all OTP logins (Principal, Parent) until real SMS; never in production                                  | `OtpProvider` implementation chosen by `OTP_PROVIDER` (`fixed` now, `sms` later); `fixed` creates a normal `otp_challenges` row hashing `OTP_FIXED_CODE` (default `999999` in local/test) and sends nothing. **Startup refuses** `OTP_PROVIDER=fixed` when `NODE_ENV=production` or `APP_ENV=production` (startup validation test). Staging allowed with demo/test data only. The code is never logged; the login is audited, not the code. Replacing it with real SMS is a production blocker (OPEN-QUESTIONS Q0) |
| A16 | One person may hold several roles; role switching only for approved assignments                                                | DB unique `(user_id, school_id, role)`; only `status = active` memberships count (guard)                                                                                                                                                                                                                                                                                                                                                                                                                           |
| A17 | Tokens carry only `sub` and `sid`                                                                                              | App (existing, tested)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| A18 | Parent is never a membership role                                                                                              | DB CHECK `school_memberships.role <> 'parent'`                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| A19 | Deprecated roles not used                                                                                                      | App: not offered; no `role_permissions` rows; DB CHECK `role NOT IN ('office_clerk','accountant','other_staff')` on new memberships (added with the expansion)                                                                                                                                                                                                                                                                                                                                                     |

## Approvals

| #   | Rule                                                                                                                                  | Enforcement                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | Principal OR Vice Principal approves; either is final                                                                                 | Permission `approvals.decide` (both roles); App: `UPDATE ... SET status = ... WHERE id = $1 AND status = 'pending'`, 0 rows = already decided (409)                                |
| P2  | Record the real approver                                                                                                              | `approval_requests.decided_by` + `approval_actions.actor_user_id/actor_role` NOT NULL (DB)                                                                                         |
| P3  | Rejection needs a reason                                                                                                              | DB CHECK `status <> 'rejected' OR length(trim(rejection_reason)) > 0`; same on `approval_actions` for `action = 'rejected'`                                                        |
| P4  | Admin edits and resubmits; full history kept                                                                                          | New row with `parent_request_id` (DB UNIQUE, so one resubmission per rejected request) and `version + 1`; App never updates a decided row; `approval_actions` append-only (grants) |
| P5  | Requester cannot approve their own request                                                                                            | DB CHECK `decided_by IS NULL OR decided_by <> requested_by`                                                                                                                        |
| P6  | V1 approval types only: teacher addition/update, timetable, results, staff leave, teacher assignment change, academic year transition | DB enum `approval_type` (no fees, attendance or admission values)                                                                                                                  |
| P7  | Teacher credentials only after approval                                                                                               | `staff.user_id` NULL and `staff.status = pending_approval` until approved (App); membership `invited` → `active` on approval                                                       |

## Academic setup

| #   | Rule                                                   | Enforcement                                                                                                                          |
| --- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| S1  | One active academic year per school                    | DB partial unique `(school_id) WHERE status = 'active'`                                                                              |
| S2  | Year transition needs approval                         | App: activating a year only through an approved `academic_year_transition` request                                                   |
| S3  | Classes 1 to 12                                        | DB CHECK `grade BETWEEN 1 AND 12`                                                                                                    |
| S4  | Sections change every year                             | `sections.academic_year_id` NOT NULL; unique `(school_id, academic_year_id, class_id, name)`                                         |
| S5  | Timings: start/end, period length; no breaks, no rooms | `school_timings` has no break or room columns; DB CHECK `day_start + period_count * period_minutes * interval '1 minute' <= day_end` |
| S6  | Working days                                           | DB CHECK `working_days <@ ARRAY[1,2,3,4,5,6,7]` and non-empty                                                                        |

## People

| #   | Rule                                                      | Enforcement                                                                                                                                                                                 |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | Student added only after offline management approval      | DB: `management_approval_confirmed` NOT NULL with CHECK `= true`; `confirmed_by_user_id`, `confirmed_at` NOT NULL                                                                           |
| E2  | Student edits are audited (old/new value, editor, reason) | App: `AuditService.record()` in the same transaction with `old_value`/`new_value`; `students.updated_by`                                                                                    |
| E3  | One student, one school; history through enrollments      | `students.school_id` NOT NULL; unique `(school_id, student_id, academic_year_id)` on enrollments; App: promotion inserts a new enrollment and sets the old status, never edits section/year |
| E4  | Roll numbers unique within a section                      | DB partial unique `(school_id, section_id, roll_number) WHERE status = 'active'`                                                                                                            |
| E5  | Non-teaching designation is free text                     | `staff.designation` text (no enum)                                                                                                                                                          |
| E6  | Teacher qualification separate from assignment            | Two tables: `teacher_subject_qualifications`, `teacher_assignments`                                                                                                                         |
| E7  | Assignment history never overwritten                      | Trigger: UPDATE on `teacher_assignments` allowed only when `OLD.valid_to IS NULL` and only `valid_to` changes; DELETE revoked from the app role                                             |
| E8  | Assignment change needs approval                          | App: new assignment rows only from an approved `teacher_assignment_change` (or the initial `teacher_addition`) request; `approval_request_id` stored                                        |
| E9  | One class teacher per section at a time                   | DB partial unique `(school_id, section_id) WHERE type = 'class_teacher' AND valid_to IS NULL`                                                                                               |
| E10 | Class teacher has no subject; subject teacher has one     | DB CHECK `(type = 'class_teacher') = (subject_id IS NULL)`                                                                                                                                  |
| E11 | Subject teacher should be qualified for the subject       | App warning (not a block: schools may assign outside qualification); listed in OPEN-QUESTIONS                                                                                               |

## Attendance and leave

| #   | Rule                                                     | Enforcement                                                                                                                                  |
| --- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Student status PRESENT or ABSENT only                    | DB enum `attendance_status` (2 values)                                                                                                       |
| T2  | One record per student per day                           | DB unique `(school_id, student_id, attendance_date)`                                                                                         |
| T3  | Teacher can edit the same day only                       | App: `attendance.mark` allowed while `attendance_date = today` in `schools.timezone`; later changes need `attendance.correct`                |
| T4  | After the day only Admin corrects, with reason and audit | Permission `attendance.correct` (Admin); `attendance_corrections.reason` NOT NULL + CHECK non-blank; audit row in the same transaction (App) |
| T5  | Bulk submit is idempotent                                | `attendance_registers` unique `(school_id, section_id, attendance_date)` and `(school_id, idempotency_key)`; App upsert                      |
| T6  | Leave is for staff only, never students                  | `leave_requests.staff_id` NOT NULL FK to `staff`; no student leave table                                                                     |
| T7  | Leave approved by Principal or VP                        | `staff_leave` approval (P1)                                                                                                                  |
| T8  | Approved leave shows on staff attendance                 | App writes `staff_attendance.status = on_leave` with `leave_request_id` on approval                                                          |
| T9  | No biometric                                             | No device/source columns                                                                                                                     |
| T10 | Leave dates valid                                        | DB CHECK `to_date >= from_date`                                                                                                              |

## Timetable

| #   | Rule                                                                                                        | Enforcement                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Y1  | Entries have period, subject, teacher only                                                                  | `timetable_entries` columns (no room, no break)                                                                                     |
| Y2  | One subject per period per section version                                                                  | DB unique `(school_id, timetable_id, day_of_week, period_no)`                                                                       |

| Y6  | Substitutes assigned manually by Admin                                                                      | Permission `substitutions.manage`; DB partial unique substitute busy once per period                                                |

## Audit

| #   | Rule                                                              | Enforcement                                                                                                                                                                                                                                                                                       |
| --- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U1  | Append-only                                                       | REVOKE UPDATE/DELETE/TRUNCATE from the app role (exists) + trigger raising on UPDATE/DELETE for everyone                                                                                                                                                                                          |
| U2  | Fields: who, role, action, module, record, old, new, reason, time | `audit_logs` columns (expanded)                                                                                                                                                                                                                                                                   |
| U3  | Never passwords, OTPs, tokens                                     | App: `AuditService` metadata typed to scalars; old/new value serialisers drop `password_hash`, `code_hash`, `token_hash`; existing secret-leak test extended to these columns                                                                                                                     |
| U4  | Role-scoped reads                                                 | Permissions: Principal `audit.read.all`; VP `audit.read.operational` (excludes categories `admin_account`, `branding`); Admin `audit.read.operational` + per-record history; Teaching/Non-Teaching `audit.read.own` (`actor_user_id = me`). App applies the filter; RLS keeps the school boundary |

**Actions that MUST write an audit row:** student create/edit/status change; guardian add/change/remove/confirm; parent link created/revoked; attendance correction; staff create/edit/status; membership/role change; credential issue and reset; password change; every approval action (submit, approve, reject, withdraw); timetable publish; result publish; notice publish; branding change; academic year create/activate/transition; teacher assignment open/close; substitution assign/cancel; import job confirm; document upload/delete; platform staff access and decisions; login success/failure/rate-limited, logout, session revoke, refresh reuse (exist today).
