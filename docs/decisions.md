# Initial technical decisions and open questions

## Decided

| Decision     | Choice                     | Reason                                                                                          |
| ------------ | -------------------------- | ----------------------------------------------------------------------------------------------- |
| Repository   | Monorepo, pnpm workspaces  | Small team, shared types, single CI                                                             |
| Node         | 24 LTS (`.node-version`)   | Current LTS line used by CI                                                                     |
| TypeScript   | 6.0.x                      | typescript-eslint currently supports up to <6.1                                                 |
| Architecture | Modular monolith           | Team size and early stage                                                                       |
| API          | NestJS, REST + OpenAPI     | Structure, guards, validation                                                                   |
| ORM          | Prisma (provisional)       | Productivity for a mixed-experience team; RLS via SQL migrations and per-request tenant context |
| Tests        | Vitest for shared packages | Fast, TS-native                                                                                 |

## Step 1 (tenancy core) decisions, agreed 2026-11-03

| Topic                       | Decision                                                                                                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Design status               | System design v1 is treated as approved                                                                                                                                                            |
| Local and CI Postgres       | Docker Compose, PostgreSQL 17                                                                                                                                                                      |
| Primary keys                | UUIDv7 generated in the app (PG 17 has no native `uuidv7()`)                                                                                                                                       |
| ORM                         | Prisma. The RLS spike is the first task of Step 1; fallback is Drizzle if it fails                                                                                                                 |
| Connection strings          | `DATABASE_URL` (app role, no `BYPASSRLS`) and `MIGRATION_DATABASE_URL` (owner role)                                                                                                                |
| Roles per membership        | A user may hold several roles in one school: unique on `(user_id, school_id, role)`                                                                                                                |
| Membership status           | `invited`, `active`, `suspended`, `revoked`                                                                                                                                                        |
| `schools` columns           | `name`, `code` (unique), `udise_code` (nullable), `status`, `shard_key` (smallint, default 0)                                                                                                      |
| `users` in Step 1           | Minimal. Phone, email and password hash arrive in Step 2 as an expand migration                                                                                                                    |
| Permissions                 | `permissions` and `role_permissions` are global (no `school_id`). Keys like `members.read`. Seed only what is in use                                                                               |
| `created_by`                | Nullable (seeded and system rows have no user)                                                                                                                                                     |
| Cross-school memberships    | Second RLS policy on `school_memberships` keyed on `app.user_id`, so login can list a user's schools                                                                                               |
| No tenant context           | Policies use `nullif(current_setting('app.school_id', true), '')::uuid`, so queries return zero rows, not an error                                                                                 |
| RLS on `schools`            | Yes: a tenant sees only its own row. Directory search gets its own path in Step 2                                                                                                                  |
| Test auth in Step 1         | A test-only identity stub. Real JWT arrives in Step 2                                                                                                                                              |
| Cross-school response       | 404 everywhere (do not reveal that the school exists)                                                                                                                                              |
| Deferred                    | Platform-staff path and `outbox_events` to Step 2; full audit to Step 7                                                                                                                            |
| `school_status` (1.3)       | `active`, `suspended` (default `active`). Verification state lives in `school_claims` (Step 2)                                                                                                     |
| RLS on `users` (1.3)        | Visible only as yourself (`app.user_id`) or as a member of the current school. Login lookup by phone/email needs its own path in Step 2                                                            |
| Guard responses (1.4)       | Not an active member: 404. Member without the permission: 403 (they already know the school exists)                                                                                                |
| Identity until Step 2 (1.4) | `IdentityResolver` defaults to "nobody", so every school route returns 401 until JWT auth lands. Tests swap in a header-based stub that lives only in `test/`                                      |
| Tenant transactions (1.4)   | One `withSchoolContext()` transaction per unit of DB work, not one held for the whole request, so connections are not held during non-DB work. The guard's check runs in its own short transaction |
| Default grants (1.5)        | `school.read`: all 10 roles. `members.read`: principal, school_admin, vice_principal. Seeded by migration; change with a new migration                                                             |
| Members list (1.5)          | Cursor pagination ordered by membership id (UUIDv7), `limit` 1-100 (default 50), filters `role` and `status`. Unknown query params return 400                                                      |
| Validation (1.5)            | Global `ValidationPipe` (class-validator) with `whitelist` and `forbidNonWhitelisted`                                                                                                              |
| Audit in Step 1             | Membership and role changes are written to `audit_logs`                                                                                                                                            |
| Observability               | NestJS Observe removed (third-party telemetry not in the design)                                                                                                                                   |
| Linting                     | Root ESLint only; oxlint removed from `apps/api`                                                                                                                                                   |

## Slice 2A (credentials, sessions, audit, error shape) decisions, agreed 2026-11-03

| Topic                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth implementation     | **Own auth** (closes open decision 4 below), behind an `AuthProvider` interface so a managed provider could replace it without touching controllers or guards. We do not use Supabase Auth                                                                                                                                                                                                                                                                                                                                                |
| OTP                     | **Not built.** `OtpProvider` (registration, password recovery) and `StepUpProvider` (change phone/password, fee refund, export) are interfaces whose default implementations answer HTTP 501 `not_enabled`. Password change and password reset return 501 until OTP is built                                                                                                                                                                                                                                                              |
| Phone and email storage | Stored in plain text, normalised (phone E.164 via `libphonenumber-js` with India as the default country; email trimmed lower case), unique, with CHECK constraints. **Deliberate deviation** from "encrypt sensitive columns" (design section 6), because login needs exact-match lookups. Revisit in the DPDP review                                                                                                                                                                                                                     |
| Pre-login lookups       | Two SECURITY DEFINER functions: `auth_find_login_user(identifier)` returns `user_id, status`; `auth_find_session_user(session_id)` returns `user_id`. Owned by `school_erp_auth_lookup` (NOLOGIN, not superuser, not table owner, so RLS applies to it as under FORCE RLS), pinned `search_path`, exact match only, EXECUTE only for `school_erp_app`                                                                                                                                                                                     |
| Access token            | JWT HS256 (pinned on sign and verify), issuer `school-erp-api`, audience `school-erp`, 15 minutes, payload only `sub` (user id) and `sid` (session id). Memberships and permissions are checked live per request. Stateless: a revoked session's access token keeps working until it expires (at most 15 minutes)                                                                                                                                                                                                                         |
| JWT secret              | From `JWT_ACCESS_SECRET`, at least 32 bytes, or the API refuses to start                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Refresh token           | `<session id>.<256-bit random secret>`; only the SHA-256 hash of the secret is stored. 30 days from login. Returned in the JSON body (a cookie for the web portal later)                                                                                                                                                                                                                                                                                                                                                                  |
| Rotation and reuse      | Rotation is one conditional `UPDATE` (matches only the current hash), so of two concurrent refreshes only one succeeds. Presenting the previous token again revokes the session. **Strict, no grace window**. Trade-off: a mobile client that retries a refresh after a lost response (or two tabs refreshing at once) is signed out on that device and must log in again. Accepted for now; revisit with real mobile retry data. A wrong secret for a valid session id is rejected without revoking (no denial of service by session id) |
| Sessions                | One row per device. `GET /v1/me/sessions`, `DELETE /v1/me/sessions/:id`, `POST /v1/auth/logout` (current device), `POST /v1/auth/logout-all` (every device). All audited                                                                                                                                                                                                                                                                                                                                                                  |
| Account enumeration     | Login: one answer (401 `invalid_credentials`) for wrong password, unknown, disabled or password-less accounts, with a dummy argon2 verify so timing matches. Refresh: one answer (401 `invalid_refresh_token`) for every failure. Password reset: 501 for every identifier                                                                                                                                                                                                                                                                |
| Passwords               | argon2id, 19 MiB, 2 iterations, 1 lane (OWASP). 10-128 characters, no composition rules                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Rate limits             | Per IP on `/v1/auth/*` (`@nestjs/throttler`, default 20/min, `AUTH_RATE_LIMIT_PER_MINUTE`). Per normalised identifier: 5 failed logins per 15 minutes (`LOGIN_FAILURES_PER_WINDOW`), unknown identifiers counted too. Both in memory (one API instance); move to Redis with slice 5. No lockout                                                                                                                                                                                                                                           |
| Trust proxy             | `TRUST_PROXY` env, off by default (otherwise `X-Forwarded-For` could dodge the IP limit)                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Disabled accounts       | `users.status` (`active`, `disabled`). Disabled users cannot log in (same answer as wrong password) or refresh                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Error shape             | `{ "error": { "code", "message", "requestId", "details?" } }` for every error. Built-in errors get generic messages (never echo request data); `details` lists validation messages (field names, never values). 500s log only the error name, code and request id                                                                                                                                                                                                                                                                         |
| Request id              | `X-Request-Id` on every response; a well-formed incoming value (8-64 of `A-Za-z0-9._-`) is reused, otherwise a UUID is generated                                                                                                                                                                                                                                                                                                                                                                                                          |
| Audit                   | `audit_logs`, append-only (app role: INSERT and SELECT only). `school_id` null for global events. Stores IP, not user agent; never the identifier typed at login, passwords or tokens. Retention to be set in the DPDP review. Events: login succeeded/failed/rate-limited, logout, logout-all, session revoked, refresh reuse detected                                                                                                                                                                                                   |
| `/v1/me` schools        | New read-only RLS policy on `schools`: a user can read schools where they have an active membership                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Non-school routes       | Isolation-suite allowlist marks each as `public` (login, refresh, password-reset, `GET /v1`) or `authenticated` (logout, logout-all, `/v1/me*`). Authenticated ones must return 401 signed out                                                                                                                                                                                                                                                                                                                                            |
| Swagger                 | UI at `/docs` and JSON at `/docs-json`, only when `APP_ENV=development`                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Structured logging      | `nestjs-pino` deferred to slice 8                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Seed                    | `pnpm --filter api run seed`: 2 demo schools, 12 demo users (principal, admin, teachers, students, parents; one user in both schools). Password from `SEED_DEMO_PASSWORD`; refuses `APP_ENV=production`; runs as the owner role; idempotent (fixed ids, upserts)                                                                                                                                                                                                                                                                          |
| Supply chain            | `argon2` allowed to run its install script (prebuilt binaries for win32-x64 and linux-x64). `@scarf/scarf` (install-time telemetry from swagger-ui-dist) explicitly denied                                                                                                                                                                                                                                                                                                                                                                |

## Open (decide before scaffolding the relevant app)

1. **Web framework:** Vite SPA vs Next.js. A login-only admin portal fits a SPA; choose Next.js if public pages or SSR are needed.
2. ~~**ORM spike**~~ **Done 2026-11-03: Prisma confirmed.** `apps/api/test/rls-spike.int-spec.ts` shows Prisma 7 (pg adapter, app role) with transaction-local `set_config` gives correct isolation: no rows without context, no leak to the next query on a reused connection or after rollback, cross-school writes blocked, concurrent schools kept apart. Finding: after a transaction-local `set_config` ends, the setting reads as `''` (not NULL) on that connection, so policies must use `nullif(..., '')`.
3. **Hosting and cloud:** Supabase-first vs AWS-from-day-one; run pricing and a small load test first.
4. ~~**Auth**~~ **Decided 2026-11-03: own auth** (NestJS-issued JWT + rotating refresh tokens) behind an `AuthProvider` interface. See slice 2A.

6. **DPDP compliance:** consent and retention design reviewed by legal counsel.
